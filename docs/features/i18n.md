# Feature: interface language (EN / FR / NL)

Status: done (2026-09-07)
Issue: none (roadmap-driven — `docs/steps`, Block X)
Branch: feat/trilingual-interface

## Problem

The roadmap is blunt about why this matters: *"Mediocre French or Dutch signals a foreign product
to a Belgian public administration, which is fatal in this market."* And `docs/roadmap.md` states
the product promise as figures a commune can use "without embarrassment: correct, dated, sourced,
and in their preferred language (en/fr/nl)."

Before this, **exactly one page was translated.** `local.html` carried a full `LocalUI.STRINGS`
table in three languages. Every other page — the commune table, the map, the national view, the
dashboard — was English only.

Worse, the licence notice was written out **five times**: three languages inside `local.html`, plus
an English copy each in `communes.html` and `map.html`. Those last two were kept in step by a test
that compared them to *each other*, which catches them diverging from one another and cannot catch
them both drifting from the French and Dutch versions. That notice is a **licence condition** on
every page publishing municipal data (`docs/data_catalog.md`), and Statbel's 2015 licence terminates
automatically on non-compliance. Five copies of it is not untidiness.

## Goal

1. One table of interface strings, in three languages, for the whole site.
2. The licence notice written **once**, and every page's copy pinned to it by test.
3. The municipal pages — `communes.html`, `map.html`, `local.html` — fully switchable, including
   indicator names, the map legend, the provenance badge and number formatting.
4. A reader with JavaScript disabled still gets a complete page, licence notice included.
5. No runtime translation calls.

## The site had TWO language systems, on two storage keys

`index.html` and `dashboard.html` were already trilingual — their own `translations` table, their
own `t()`, their own switcher — from before the shared module existed. They persisted the reader's
choice under `lang`. `local.html` used `belpulse-lang`.

**So choosing French on the dashboard and clicking through to the commune table gave you English.**
Reproduced in a browser before fixing, not inferred.

Those two pages now write the canonical `belpulse-lang`, and `I18N.initial()` still *reads* the old
`lang` as a fallback so nobody who had already chosen a language is reset by the change. Their own
translation tables are left alone: they are complete, they are proofread, and rewriting a 1,091-line
page's string handling to save a duplicate mechanism would be a large change with no reader-visible
benefit. What matters is that one choice now carries across every page, which is verified end to
end in a browser.

## The static pages, in three languages

`local/{nis}/` (English, unchanged — already indexed and linked), `local/{nis}/fr/`,
`local/{nis}/nl/`. **565 pages became 1,695; 12 MB became 40 MB.**

That is the trade the maintainer approved, and it is the point of the exercise: a bourgmestre
searches in French, and these static pages are the only thing this repository publishes that a
search engine can read without executing JavaScript.

Three details make it work rather than backfire:

- **`hreflang` on every page, naming all three plus `x-default`.** Without it a search engine treats
  the three as duplicates competing with each other, and generating them can make the ranking
  *worse*. Each page's `canonical` is itself, not the English page: three real pages, not three
  views of one.
- **The sitemap lists all three routes**, each declaring its alternates through `xhtml:link`. A
  sitemap listing only English would leave the others to be found by crawl alone.
- **The link prefix is computed from the language**, because a translated page sits one directory
  deeper. A wrong prefix breaks every link and asset on the page while the page itself still
  renders — the kind of breakage that ships.

The licence notice is no longer scraped out of `communes.html`'s markup: that worked with one
language and is impossible with three. `scripts/export_local_pages.py` reads all three notices from
`assets/i18n.js` through node, and **refuses to generate anything** if a language has none — Statbel's
2015 licence terminates automatically on non-compliance, so that has to stop the build.

Numbers are written the way each language writes them: `565,615` / `565 615` / `565.615`. Done by
substitution rather than through Python's `locale` module, which is process-global and depends on
which locales the host happens to have generated.

Rebuilds stay byte-identical across all 1,695 pages, verified with a changed build id.

## Non-goals

- Machine translation of anything. Every string here was written by hand and is reviewable, which
  is the point of `[H] Get native FR and NL proofreading` being a separate roadmap step.
- Consolidating `index.html`'s and `dashboard.html`'s own translation tables into the shared module.
  See above: they work, and the reader-visible problem was the storage key, which is fixed.

## Approach

### One module: `assets/i18n.js`

The repo's second shared frontend asset, after `assets/commune_map.js`. It holds:

- `LANGS`, `DEFAULT_LANG`, `STORAGE_KEY`
- `STRINGS` — 81 keys × 3 languages, interface chrome only
- `t(lang, key, vars)` — substitution, falling back to English and then to the key
- `initial(storage, navigatorLanguage)` — an explicit choice, else the browser's preference, else
  English

**`STORAGE_KEY` is `belpulse-lang`**, the key `local.html` has always used. Changing it would
silently reset the stored choice of every existing reader.

**What is deliberately NOT in this file:** indicator names, section labels, source labels, licence
notes per source and the grade words. Those travel in the payloads from the `indicators` table and
the configs (rules 2 and 7), so a label cannot drift from the data it describes. What lives here is
what the site says about *itself*.

### `data-t` on the markup, English left in place

Five attributes are swapped: `data-t` (text), `data-t-html` (text with links), `data-t-title`,
`data-t-aria` and `data-t-placeholder`. A placeholder and an aria-label are as user-facing as body
text, and a page translated only in its visible prose is half translated.

**The English stays in the HTML.** The strings file *replaces* text; it does not supply it. A reader
whose JavaScript never runs gets a complete page — verified in a real browser with scripting
disabled — and, critically, still gets the licence notice. (The static pages get their own copy of
the notice from the same strings file, per language; see below.)

### The shared map component holds no English

`assets/commune_map.js` reads every user-facing sentence through `MapUI.text(lang, key)` from the
same table, and takes a `lang` option plus a `setLang()` that re-languages in place — the paths and
the reader's current view are untouched, only the words change. A test asserts the component
contains no prose literal of its own: it is loaded by pages in three languages, so a sentence left
inside it would show in English on all of them.

### Numbers follow the reader, not the browser

`toLocaleString(undefined, …)` takes the *browser's* locale, which is the one thing on the page the
reader did not choose. A French page read in an English browser printed `35,363` where Belgium
expects `35 363`, and Dutch expects `35.363`. The language now flows into every format call.

### One licence notice

The three-language notice moved out of `local.html` into `I18N.STRINGS[lang].attribution`, and
`communes.html` and `map.html` carry the English rendering of that exact string in their markup. The
old page-shaped wording ("the derived **columns** marked above", "the employment **section**") is
gone: the licence requires naming the source and what changed, not describing the page furniture,
and page-shaped wording is *why* there were five variants.

`map.html` keeps a second notice of its own — the boundary file's — now also in three languages.

The test that compared two pages to each other is replaced by one that renders the canonical string
through node and pins every page's markup to it. And `test_statbel_attribution.py`'s notion of "the
page" widened to **the licence surface**: the page's own markup *plus* the shared strings it
renders. Reading only the file would let all 47 obligation assertions pass vacuously on a page whose
notice had been deleted from the module.

## Tests

`tests/test_i18n.py`:

- every key exists in every language (both `t()` implementations fall back to English silently, so
  an omission is invisible in testing and visible only to a French reader)
- no multi-word prose string is left identical to its English (short words like "Province" and
  "Auto" legitimately match, so only prose is checked)
- placeholders survive translation — a translation that drops `{n}` renders a sentence with a hole,
  one that invents `{total}` renders a brace to the reader
- the notice names all three sources in every language and disclaims CC BY for the two it does not
  cover
- an explicit choice beats the browser; a Belgian French browser opens in French; junk in storage is
  not trusted
- every `data-t` key a page asks for exists (a typo renders the key on screen, in English too,
  because the fallback *is* the key)
- the English remains in the markup, so a page has a heading and a licence notice without scripting
- the map component holds no prose literal of its own

## Rollout / risks

- **A key present in English and missing elsewhere is silent.** That is what the completeness test
  is for, and why it fails rather than warns.
- **The licence notice is now a single point of failure.** That is the intended trade: one string
  that every page is pinned to, instead of five that drift. The pinning test is what makes it safe.
- ~~**The static pages are still English.**~~ Resolved in this same feature — see "The static
  pages, in three languages" above: 565 pages became 1,695 and a French reader gets a French
  crawler-visible page. This line stayed here, contradicting the section two screens up, until
  Batch 15c went looking. A risk register that outlives the risk teaches people to skim it.
- **The block-built pages (`/preview/…`) are trilingual too, as of Batch 15c**, with the same
  `hreflang` + `x-default` + self-canonical shape and the licence notice read per language from
  this file's own strings table. They are in **no sitemap** — there is still no root `sitemap.xml`
  and no `robots.txt` — so they are reachable but not discoverable. Batch 17 owns the route
  inventory (`docs/implementation/known-risks.md:37`) and should close this with it.
